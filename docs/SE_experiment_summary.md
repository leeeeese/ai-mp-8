- 현상: 첫 전체 실행에서 단순 요건 6건 **모두**에 "상세 분석 권장"이 붙음 (사용자가 매번 재분석을 누르게 됨).
- 원인: 여러 진입점·공통 모듈 신호를 [참조] 노드에서도 세고, 신호가 하나라도 있으면 (LLM 판단 포함) 모두 '권장'으로 노출.
- 조치: [변경] 노드의 신호만 인정 + 강한 신호만 '권장', 약한 신호는 '참고'로 → v1 에서 **6 → 0**. 이후 0~1건.

### 5-2. 영역 없는 경로가 결과에서 사라짐 (11-02 v1)

- 현상: H-2 정답 노드 `MOD:ProdScrbSvc.checkScrbAvail` 이 결과·레포트·KPI 어디에도 기록 없이 빠짐.
- 원인: Logic 노드에서 시작한 경로는 진입점(화면·배치)이 없어 영역을 못 정함 → 어느 영역 경로에도 안 들어감.
- 조치: SE 는 영역 추정(`assign_orphan_areas`)으로 임시 대응 (v2), 근본 해결은 YJ 에 진입점 역추적 요청 → v6-5 반영.

### 5-3. 프롬프트 확장이 오히려 나빠짐 (11-03 v3 → v3-fixed) ★

- 배경: v3 에서 정답 변경 노드 44개 중 22개를 [변경] 으로 놓침 (LLM [참조] 판정 다수).
- 시도: Simulator 프롬프트에 "구조가 그대로여도 변경인 경우" 4가지(데이터 등록·보정, 분기·검증 추가, 화면 전달·표시, 오류 조치)를 명시.
- 결과 (같은 상류로 비교): [변경] 정밀도 **0.964 → 0.839**, 재현율 0.549 → 0.529. M-2 에 오탐 3개(`TB_PAY_SAFE_NOTI` 컬럼 2개, `TB_CNTC_HST`), H-2 오탐 1 → 2.
- 조치: 프롬프트 확장 원복 (`61029e2`), 반복 실험 체계 도입. 원복한 기준을 3회 반복(base)해 정밀도 0.92 · 재현율 0.62 로 재확인.
- 배운 점: "변경으로 보라"는 지시를 넓히면 **재현율은 안 오르고 오탐만 는다.** 한 번 실행 결과로 판단하지 않는다.

## 6. 실패에서 배운 점 (발표용 메시지)

1. **신호는 강약을 나눠야 쓸모가 있다.** 신호가 하나라도 있으면 권장하던 방식은 단순 요건 6/6 에 권장을 붙였다 → 강한 신호만 권장해 0건.
2. **"더 넓게 보라"는 프롬프트는 오탐만 늘렸다.** 같은 입력으로 비교하니 정밀도 0.96 → 0.84, 재현율은 그대로 → 원복. 프롬프트 변경은 상류 고정 비교로 검증한다.
3. **한 번 실행으로는 판단할 수 없다.** 같은 입력으로도 정밀도가 ±0.04, 같은 코드로 L-1 이 2/7 ↔ 7/7 → 3회 반복 · 평균 · 범위로 비교하는 실험 체계를 만들었다.
4. **지표가 문제를 가릴 수 있다.** 노드 정밀도(0.11)는 경로 수에 묶여 SE 판정을 못 보여 줬다 → [변경] 노드 정밀도로 주 지표를 바꿨고, 운영 문의는 [변경] 재현율에서 뺐다.
5. **재분석은 판정을 고치지만 빠진 노드는 못 살린다** (SC-003). 상류 탐색 보완(공통코드 규칙)이 근본 해결이었다.
6. **남은 과제는 보수적 [참조] 판정** (놓친 노드의 약 70%, 버전과 무관하게 16~18개).
7. **데모와 실사용은 다르다.** 실제 API 로 돌려 보니 언어 이탈 · LLM 무응답 · 세션 유실 같은 운영 문제가 나왔다.
